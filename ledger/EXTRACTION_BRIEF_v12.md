# Ledger extraction brief, version 1.2 (cutoff 2026-10-28)

Read `PROTOCOL.md` (including the rating anchors) and `SCHEMA.md` in this folder first. The extraction records measured quantities about typed probabilistic decision models: models that map a state and a caller-declared question with a finite answer space to a probability distribution over the declared options in one forward pass, without generating free text. Examples are the hosted Jev (TypeSafe, versions jev-1.13.0 and jev-1.14), other hosted models (Microsoft Decision-1, MachineFi Trio-Spark, Cloudflare Clef), and open ones (Laya, Kev, Nimble, decider, this-that, pplx-decider and many reimplementations). The cutoff is 2026-10-28. Record only what each paper itself says, and import no fact from another source.

For each assigned paper:

1. **Full text.** Try `https://arxiv.org/html/<id>` first (curl with `-L -A "Mozilla/5.0"`, save to `../ledger/fulltext/<id>.html`). If that fails, download `https://arxiv.org/pdf/<id>` to `fulltext/<id>.pdf` and read the PDF. Wait at least 3 s between arXiv requests; on an empty or 429 response wait 30 s and retry, up to 4 times. Also save a plain-text copy as `fulltext/<id>.txt` when possible (HTML tags stripped).
2. **Study note.** Write `studies/<study_key>.md` (study_key = first-author surname + year + first content word of the title, lowercase ASCII, for example `deusser2026evaluating`; if the key already exists in `studies/`, append a letter). It records the arXiv ID and version, authors with affiliations and affiliation type, the task and data, every decision model evaluated with its exact version or revision, the comparators and how they were prompted or tuned (tuning-budget parity), the reference labels and how they were made (human adjudicated, human crowd, LLM teacher, model consensus, administrative field, task outcome, synthetic), n, the sampling design and intervals, whether the test data predate 2026 and could be in training data, cost and latency with hardware or provider, calibration analysis (binning, recalibration), cascade or escalation results, option-name, cardinality, language or robustness tests, code and data availability, and the paper's own limitations. Every factual line cites a location (section, table, figure or page).
3. **Ledger rows.** Rows go to the batch's part file `parts/ledger_Vnn.csv`, using exactly the SCHEMA.md columns in that order, one row per (model, task or dataset, metric) for the headline and decision-relevant quantities: main accuracy or agreement for each decision model and the best comparator, calibration, cost and latency ratios, cascade results, robustness effects. Aim for 5 to 25 rows per paper and skip minor ablations. `value` is written exactly as reported (same precision, no % sign, unit in the metric name, for example `accuracy_pct`). `excerpt` is the verbatim sentence or table cell (for a table, quote the caption plus the row and column), and `location` says where. Row IDs come from the batch's range. `value_key` is `<study_key>.<camelCaseDescriptor>` and must be unique. `extractor` is the batch label (for example `batch V3`) and `ledger_version` to `1.2`.
4. **Not an evaluation.** If the paper turns out not to measure a decision model as defined above (for example it only mentions Jev, or uses an unrelated "decision model"), it gets no ledger rows, and its study note says why in one line.

Risk of bias is graded separately, from the study note and the full text (`GRADING_BRIEF_v12.md`). Numbers are never paraphrased, and a number shown only in a figure is read only if the figure labels it.
