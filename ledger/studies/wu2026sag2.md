# wu2026sag2 — SAG2: Embedding-Free Multi-Hop Retrieval with BM25 and JEV

arXiv:2610.22588v1 [cs.CL], 15 Oct 2026. HTML retrieved 2026-10-28 (fulltext/2610.22588.html, .txt). Coder: batch V16. Classified as an application paper: Jev is a component, and all numbers are pipeline-level retrieval results, with a few ablations that isolate the Jev scoring contribution.

## Authors and affiliation

Yuchao Wu (sole author), Zleap AI (jomy@zleap.com). Affiliation type: industry. The same author wrote the SAG comparator (Wu et al. 2026, arXiv:2606.15971), so the comparison is against the author's own prior system (§4.2).

## Task and data

Multi-hop passage retrieval. BM25 (SQLite FTS5) supplies candidates; Jev through its Noul (yes-probability) interface scores each candidate as to whether it supplies a necessary fact in the answer chain, given the question and shared retrieved context; the top passages seed lexical term expansion for up to two further rounds (§3). Data: 1,000-question development subsets of MuSiQue (corpus 11,656 passages; 518 two-hop, 316 three-hop, 166 four-hop), 2WikiMultiHopQA (corpus 6,119) and HotpotQA, following the SAG evaluation setting with supporting and distractor passages pooled (§4.1, Table A2); and EnterpriseRAG-Bench, 511,962 documents, 470 of 500 questions with document labels (§5.2). Metrics R@k and AE@k (complete-evidence coverage). Retrieval only; no answer generation (§4.1).

## Decision model and version

JEV Noul interface via OpenRouter; "the returned model is typesafe/jev-1.13-20260917" (§4.3). TypeSafe API docs accessed October 14 and 15, 2026 (references). Concurrency 20. Question: a passage judgment is one candidate scored under a particular question and context; maximum 340 judgments per question under default limits (§3.5). Jev output is used only as a ranking score, not as a calibrated probability.

## Comparators and tuning parity

Dense and structure-augmented baselines (Contriever, BGE-Large-EN-v1.5, GTE-Qwen2-7B, GritLM-7B, NV-Embed-v2, HippoRAG 2, SAG) are copied from Wu et al. (2026), not rerun (Table 1 caption); BM25 is rerun on the same subsets. SAG uses BGE-Large and Qwen3.6-Flash with MySQL and Elasticsearch, so the comparison is system versus system with different decision components (§4.2). Controlled MuSiQue ablations (expansion depth, matched judgment budget, no shared context, final-only Jev, RM3, GAR-BM25) share the same questions (§4.2, App. B). EnterpriseRAG-Bench baselines (BM25, vector, Bash Agent) are published values from Sun et al. (2026); the Bash Agent has a different output budget, and "does not establish equivalent compute budgets" (§5.2). No tuning data given for baselines. MuSiQue "was also used during method development" (§5.5), so the SAG2 hyperparameters were set on the evaluation data.

## Reference labels

Annotated supporting passages of the public multi-hop datasets (annotation procedure not described in the paper; coded administrative_field). EnterpriseRAG-Bench is a synthetic corpus with released document identifiers (§5.5, coded synthetic).

## n, intervals

1,000 questions per dataset; 470 for Enterprise. Paired 95% percentile bootstrap (2,000 question resamples, seed 20261015) is used only for the MuSiQue comparisons (§4.3); Table 1 and the Enterprise table carry no intervals. Intervals "do not quantify variation across repeated model runs." Single run.

## Test-set exposure

All four data sources are public and released before Oct 2026 (MuSiQue, 2Wiki, HotpotQA pre-2026; EnterpriseRAG-Bench arXiv 2605.05253). No contamination check; the dev subsets are public. Jev training data unknown.

## Cost and latency

MuSiQue: 11,656 passages indexed in 2.36 s, 25.87 MiB, zero offline model calls; model charges $0.433769 per 100 queries and $4.326379 per 1,000 queries; 331,325 judgments for the H=2 setting (§5.3, §5.4, Table 3). "Online latency is not reported because service waiting time was not separated from concurrent execution." Charges exclude machine rental and answer generation.

## Calibration and cascade

None. Jev scores are used for ranking only. No calibration analysis, no escalation.

## Robustness

No option-name, order, language or cardinality tests. Ablations: expansion depth H=0/1/2 (R@10 67.93, 83.36, 86.62), no shared context (76.25), final-only Jev, RM3 and GAR-BM25 variants (App. A, B).

## Code and data

Evaluation code https://github.com/Zleap-AI/SAG-Benchmark; questions and candidate text are sent to the hosted Jev service (Code Availability). The Jev model itself is hosted and closed.

## Paper's own limitations (§5.5)

Dependence on a closed hosted Jev release (architecture and weights not public; cannot be run on premises); does not isolate every term-weight factor or show Jev beats other decision models; SAG comparison uses different models and implementations; fixed development subsets and MuSiQue used in development; generalization to unused splits, private corpora and answer generation unevaluated; Enterprise corpus synthetic; lexical access can miss paraphrases; low complete-evidence coverage on four-hop questions; cost study covers one corpus.
