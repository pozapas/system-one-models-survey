# zhan2026dyad — Dyad: Extending Large Language Models with Native Typed Decision-Making

arXiv:2609.36116v1 [cs.LG], 28 Sep 2026 (version from the HTML header and the 2609.36116v1 asset paths). Full text: fulltext/2609.36116.html and .txt. Method paper: a pretrained LLM gains an environment-conditioned action encoder whose embeddings of caller-supplied candidate actions are scored against the LLM hidden state into a softmax over typed actions (Sec 2.2, Eq. 3). Included because Dyad is a typed decision model and is measured against Jev on JevBench (Sec 5.4, Table 5).

## Task and data
Two strands. (1) Sequential environment control: RL on DIVE or CodeGym, then transfer evaluation without further training on ALFWorld, WebShop, tau2-bench and a 100-task subset of SWE-bench Verified; separate in-domain runs on ALFWorld and WebShop (Sec 5.1, App. B.1). General capability retention on MMLU-Pro (12,032 questions), HMMT February 2026 (33 problems, avg@4) and LiveCodeBench v6 (1,055 problems) (App. B.2, Figure 3, Table 11). (2) Standalone typed decisions: JevBench public subset of 231 items (48 Easy, 72 Standard, 111 Hard), covering categorical choices, yes/no judgments and ordinal ratings (App. B.3).

## Decision models evaluated
Dyad on Qwen3.5-4B, 9B and 27B with joint optimization, and on Qwen3.5-4B, 9B, Llama-3.2-3B-Instruct and Gemma-4-E2B-it with the LLM frozen (Sec 5.1). Attention pooling is the default projector (Sec 5.1). For JevBench the model is Qwen3.5-4B + Dyad trained on CodeGym with GRPO, in two variants: with reasoning (mean 120.44 output tokens before the answer) and without reasoning (Table 5, Sec 5.4). Only the variant without reasoning is a single-pass typed decision; the variant with reasoning generates text first (Table 5). No checkpoint, revision or release is given for any Dyad model (Sec 1 says the pipeline is planned to be open-sourced).
Jev, printed as "Jev 1.13" in Table 5, with no run or access date (Table 5, App. B.3). Jev also appears in the ALFWorld comparison of Figure 5, where its version and setup are not stated (Sec 5.4).

## Comparators and tuning parity
Environment strand: Dyad-GRPO against GRPO and Dyad-GiGPO against GiGPO with the same LLM and RL training environment, and each untrained base model as reference (Sec 5.1). RL hyperparameters are listed per environment for joint post-training, with no tuning per method described (App. B.4, Table 10). JevBench strand: Jev 1.13, zero-shot Qwen3.5-4B with and without reasoning, and the two Dyad variants (Table 5). Dyad is RL-trained on CodeGym, not on JevBench, so the JevBench items are out of domain for it (Sec 5.4). The JevBench prompt for any system is not given; the prompt templates in App. B.5 cover only the environments. The paper does not say whether the authors ran Jev on JevBench themselves; only the Jev latency is stated to come from the benchmark's published per-item API timings (App. B.3). The link target of that timing source is the jevbench repository at commit 1bcc55eb, results/v1.2 (App. B.3, link target). No Jev output-token count is available (App. B.3).

## Headline numbers and their sources
The abstract's 3.80 average absolute ALFWorld gain with the 9B model equals the mean of the two Table 2 ALFWorld gains, 5.89 for GRPO (90.90 against 85.01) and 1.70 for GiGPO (91.02 against 89.32), so it is coded as in-domain (Abstract; Sec 5.2, Table 2). Table 2 does not name its metric; the rows use in_domain_score_pct for that reason (Table 2). Table 7 names its metric as success rate (App. A.1, Table 7).

## Reference labels
JevBench: the paper does not say how the answer key was made (App. B.3), recorded as not_reported. Environment tasks: task outcome from each environment's verifier or tests (Sec 2.1, App. B.1). Action-encoder initialization data are synthetic, with task context and reasoning generated by GPT-5.5 for preselected targets (Sec 3.1, App. A.2).

## n and intervals
JevBench n = 231 (48/72/111) (App. B.3). Overall is the item-weighted average of the tiers (App. B.3), and it reconciles with the printed tier values for Jev (85.01) and Dyad with reasoning (86.18) (Table 5). The tier accuracies are not whole-item fractions of the tier sizes (for example 96.79 of 72 items and 70.88 of 111 items) (Table 5), so Table 5 is probably an average over runs, but the paper states no run count for it. Environment results use 3 seeds (Tables 2, 3, 4 captions; Figure 3 caption); no standard deviations or intervals are printed in the tables; Figure 4 shading shows plus or minus one standard deviation of training curves (Figure 4 caption). The number of evaluation episodes per environment is not stated; Table 9 lists environment task counts (ALFWorld 3,827, WebShop 11,687, tau2-bench 278, SWE 500) (App. B.1, Table 9).

## Test-data exposure
JevBench public subset from a public GitHub repository; the paper gives no release date and no contamination check (App. B.3). ALFWorld (2021) and WebShop (2022) are public pre-2026 benchmarks (Sec 5.1, references). tau2-bench (2026) and HMMT February 2026 are recent; LiveCodeBench v6 problems date from May 2023 to April 2025 (App. B.1, B.2). The alignment test split had been used in earlier model selection and is a diagnostic, not an independent holdout; checks do not establish disjointness from downstream benchmark actions (App. A.2).

## Cost and latency
JevBench mean latency until the complete response: Dyad without reasoning 0.31 s, Dyad with reasoning 1.35 s, Qwen3.5-4B without reasoning 0.32 s, with reasoning 1.02 s, Jev 0.67 s (Table 5). The Jev figure is recomputed from published per-item API timings from a separate evaluation, includes network overhead, and the authors state the deployments do not establish a matched-hardware speed comparison (App. B.3). Dyad hardware is not reported; inference uses vLLM (Sec 5.1). No monetary cost is reported. Action embeddings can be cached and reused across steps (Sec 2.2).

## Option-name, cardinality, robustness tests
Action-description format: MCP-style descriptions beat natural-language ones by 2.87 points on ALFWorld and 4.39 on WebShop, but the authors note this does not isolate format from description length and content (App. A.1, Table 7). Permutation equivariance over the rows of the scoring matrix is a design property, not a measured test, and does not cover reordering descriptions inside the encoder or LLM input (Sec 2.2, App. A.1). Projector ablation: attention pooling 55.92, MLP-weighted 48.20, mean pooling 41.23 validation reward (Table 6). Frozen-LLM gains are not universal: Llama-3.2-3B-Instruct on tau2-bench (-0.28) and Gemma-4-E2B-it on SWE (-0.51) decline (Table 4). Dyad does not outperform its RL baseline in the remaining 7 of 48 cross-environment comparisons (Sec 5.2, Table 3). No language or option-count sweep.

## Code and data availability
Not released; the inference and training pipeline is planned to be open-sourced (Sec 1). JevBench is public on GitHub (App. B.3).

## Authors' limitations
The Jev latency is not a matched-hardware comparison (App. B.3). The format comparison does not isolate formatting from length and content (App. A.1). The alignment test split is not a historically independent holdout (App. A.2). Environment interface counts do not measure decision complexity (App. B.1). Training curves are compared only within each environment and model scale because budgets differ (App. B.4). Dyad does not remove capability degradation in every task-specific setting (App. C.1). No separate limitations section.
