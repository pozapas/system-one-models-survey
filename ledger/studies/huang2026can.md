## Task and data

**RadEvalX** — "RadEvalX contains 100 IU-Xray reference reports, each paired with one M2Tr-generated report [5, 7]. Two radiologists reached consensus on significant and insignificant error counts across eight categories. The sample contains 80 abnormal and 20 normal reports, selected after stratification by RadCliQ scores." (§4.1) "We evaluate total and clinically significant error counts over all eight categories; a six-category sensitivity analysis excludes the two uncertainty categories (Appendix A)." "There are 100 distinct report IDs but 96 distinct reference texts and 78 candidate texts... Each ID has only one candidate, so within-study candidate ranking is unavailable on RadEvalX." (Appendix A)

**RadEvalExpert** — "RadEvalExpert contains 624 pairs from 208 studies, with three model-generated candidates per reference [18]. It covers findings and impression sections and supplies total and significant error labels. We keep each study together during uncertainty estimation." (§4.1)

**"Expert error counts"** are the two datasets' reference labels: radiologist-assigned counts of factual errors (total, and the subset judged clinically significant) per report/candidate, used as the ground truth that Jev's discrepancy scores are correlated against (Kendall τ_b).

**Question-set conditions** (§3.4, Appendix B.1): "OneQ uses only the support question." This is the "single-question configuration" and is literally the same thing as "one support question per statement" — OneQ asks one three-way support/contradiction/not-addressed question per statement against the opposing report, in both directions. "Full adds four negation/uncertainty questions, a discrepancy-type question, and a clinical significance question." That totals seven questions per statement: 1 support + 4 noul (claim_negated, claim_hedged, report_negated, report_hedged) + 1 error_type (choice) + 1 significance (score) = seven. "Full also applies a negation-consistency correction: if the claim and report negation probabilities differ by more than 0.5 while p_s > 0.5, half of p_s is moved to p_c. OneQ has no negation outputs, so this correction is inactive."

**False negation and the controlled-error test**: "In a separate controlled-error test, Jev detects false negation with an AUROC of 0.977." (Abstract) False negation is defined by example: "Changing 'a pleural effusion' to 'no pleural effusion' preserves most words while reversing the finding" (§1) — i.e., turning a present finding into an absent one via negation. The controlled-error test uses **ReXErr**: "The ReXErr sentence test set contains 19,859 examples [15]. Excluding 346 neutral rewrites leaves 19,513 examples: 8,723 injected-error sentences and 10,790 unchanged sentences. Each candidate sentence is judged against its complete original report. This experiment uses the raw support probabilities from the Full question set, without atomic decomposition or negation correction." (§4.1) ReXErr-v1 (Rao et al. 2025) is a PhysioNet dataset of controlled/injected chest-X-ray report errors derived from MIMIC-CXR (ref [15]); "false negation" is one of 11 positive injected-error types, with n₊ = 1,398 (Table A9).

## Decision model and comparators

**Jev**: "Our implementation, S1Fact, uses Jev version **jev-1.13.0**. L1 uses temperature-zero local inference." (§4.2) Ref [16]: "TypeSafe AI (2026) Jev 1.13: Models and System One documentation. Note: Model jev-1.13.0; accessed September 22, 2026."

**Open NLI judge**: "The open judge uses **DeBERTa-v3-large-mnli-fever-anli-ling-wanli** [12]. The opposing report is the premise and the statement is the hypothesis. Entailment, contradiction, and neutral probabilities map to p_s, p_c, p_u. It shares L1 statements and Eq. 2 with OneQ; its tokenizer uses a maximum sequence length of 512 tokens." (§3.4) Ref [12] resolves (via the HTML hyperlink) to `https://huggingface.co/MoritzLaurer/DeBERTa-v3-large-mnli-fever-anli-ling-wanli` — this confirms the HF id flagged in the task is the **open NLI judge**, not RadMatch.

**Local RadMatch — distinct model, not the DeBERTa checkpoint.** RadMatch is cited separately as ref [6]: "C. Corbiere, L. Machado, A. Charley, B. Callard, P. Manceron, and C. Dancette (2026) RadMatch: Auditable Radiology Report Evaluation via Finding-Level Matching. arXiv preprint arXiv:2609.01470." Its role in this paper: "RadMatch uses finding-level matching and attribute analysis to produce auditable discrepancy measures [6]." (§2) It is not a fine-tuned classifier like the DeBERTa checkpoint; it is an LLM-driven finding-matching/attribute-analysis pipeline (i.e., a prompted procedure, not a distinct set of trained weights of its own) that the authors run locally: "Both generative baselines use a local Qwen3.8-27B-FP8 backend on two 32 GB RTX 5090 D GPUs. This replaces the original papers' judge choices... RadMatch retried 52 pairs and used validation fallback on 11; its default backend configuration sampled at temperature 1.0." (§4.2) "RadFact and RadMatch use local Qwen3.8-27B-FP8 at temperatures 0 and 1, respectively (Section 4.2)." (Table 1 caption) So "Local RadMatch" = the RadMatch procedure/prompting pipeline (Corbiere et al. 2026) executed on a locally hosted Qwen3.8-27B-FP8 model, substituted for whatever judge model the original RadMatch paper used. **This is a wholly different system from the DeBERTa NLI comparator** — different architecture (agentic LLM pipeline with finding-level matching/validation/retry logic vs. a single-pass NLI classifier), different backend model (Qwen3.8-27B-FP8 vs. DeBERTa-v3-large), and different citation.

**Other baselines/comparators** (§4.2): "The main comparators include GREEN, RadCliQ, RadGraph F1, BERTScore, Temporal F1, open NLI, and the finding-count baseline n + m. RadEval supplies the standard metric implementations [18]. We also run RadFact and RadMatch on all 100 RadEvalX pairs and a fixed random subset of 200 RadEvalExpert pairs." RadFact also runs on the local Qwen3.8-27B-FP8 backend at temperature zero. GREEN uses greedy decoding.

## Reference labels

Total/significant error counts for RadEvalX come from "two radiologists reach[ing] consensus" (§4.1) — human_adjudicated, n=100 report pairs (8 error categories; a 6-category sensitivity variant is also reported, Appendix A / Table A1). RadEvalExpert "supplies total and significant error labels" from its own expert annotation protocol (RadEval framework, ref [18]) — human_adjudicated, n=624 pairs from 208 studies (3 candidates/study). A fixed 200-pair RadEvalExpert subset (138 studies) is used for the RadFact/RadMatch comparisons (Panel B of Table 1).

## Sampling design and test-set exposure

RadEvalX: stratified by RadCliQ score, 80 abnormal + 20 normal (§4.1); PhysioNet release, version 1.0.0, public prior to this paper. RadEvalExpert: all 624 pairs used for the main comparators; RadFact/RadMatch restricted to "a fixed random subset of 200 RadEvalExpert pairs" and "all subset comparisons use exactly the same valid pairs" (§4.2). ReXErr-v1 (PhysioNet, version 1.0.0) supplies the controlled-error sentence set; a 2,000-pair sample of ReXErr report pairs is used "for cost and report-level diagnostics" (§4.1). All datasets (RadEvalX, RadEvalExpert, ReXErr-v1, RaTE-Eval) are public releases predating this evaluation (test_set_exposure: public-pre-2026).

## Cost

"Judgment API calls cost less than US$0.03 per 100 report pairs, excluding local decomposition." (Abstract) The exact per-pair figures: "OneQ's judgment API cost is approximately $0.000226 and $0.000258 per pair, excluding local decomposition. In practical terms, the judgment API costs about 2.3–2.6 cents per hundred report pairs." (§5.3) Table A8 gives the underlying token/cost table: RadEvalX Full = 9,695.17 tokens/pair, $0.00040720/pair; RadEvalX OneQ = 5,374.55 tokens/pair, $0.00022573/pair; RadEvalExpert Full = 10,797.20 tokens/pair, $0.00045348/pair; RadEvalExpert OneQ = 6,151.13 tokens/pair, $0.00025835/pair. Price basis: "$0.042 per million input tokens; output tokens are free [16]." (§4.3) "**Excluding local decomposition**" means this price covers only the Jev judgment API calls (the support/discrepancy questions); it excludes the cost of running the local Qwen3.5-9B atomic-decomposition step that produces L1 statements (that step runs on the authors' own GPUs, not billed per-token via an API) — "Full and OneQ use the same L1 decomposition, so its local cost is shared." (Appendix E)

**Token-reduction figure**: "On RadEvalX, Full uses 9,695.17 input tokens per pair and OneQ uses 5,374.55, a 44.56% reduction... On RadEvalExpert, the corresponding means are 10,797.20 and 6,151.13, a 43.03% reduction." (§5.3) Reported in the abstract as "43–45% fewer judgment input tokens."

## Calibration

Not part of the report-level Kendall/AUROC headline analysis, but a distinct §5.6/Appendix G analysis exists: "Jev's raw sentence-level probabilities have ECE 0.1192 on the full test set, compared with 0.1045 for NLI. On the separate calibration holdout, Jev's ECE falls from 0.1235 to 0.0077 after isotonic calibration. NLI improves from 0.1072 to 0.0063 under the same procedure." (§5.6) Table A10 (9,951-example holdout, fit on 9,562 disjoint-study examples): Jev raw ECE 0.1235/Brier 0.1269/AUROC 0.8858; Jev logistic ECE 0.0129; Jev isotonic ECE 0.0077. Open NLI raw ECE 0.1072/Brier 0.1224/AUROC 0.8938; isotonic ECE 0.0063. This calibration analysis is on the sentence-level ReXErr task (Full's raw support outputs), not on the report-level OneQ pipeline. The AUROC 0.977 for false-negation detection (main text, Table A9 gives the more precise 0.9773 [0.972, 0.982]) is computed as the ROC AUC of Jev's raw support-question contradiction/negative probability against the binary label "sentence has an injected false-negation error vs. unchanged," pooling the 1,398 false-negation positives against the same 10,790 unchanged negative sentences used throughout the error-scope tables.

## Cascade/escalation

No cascade or escalation-to-a-stronger-judge mechanism is described anywhere in the paper (no tiered/cascaded evaluation pipeline; OneQ vs. Full are alternative fixed configurations, not a cascade).

## Finding-count and error-scope robustness (§5.5, Table 2/Figure 4)

"We compare Jev with a finding-count baseline to assess the contribution of its support judgments beyond report size. Counting extracted findings alone reaches τ_b = 0.288 on RadEvalX and 0.261 on RadEvalExpert... OneQ improves over it by 0.285 [0.157, 0.416] and 0.137 [0.080, 0.197], respectively." "On RadEvalExpert, OneQ also orders candidates describing the same examination better than finding count in point estimate: 0.205 versus 0.101 (Figure 4)." Within-study analysis (69 comparisons on the shared 200-pair subset): "both Jev configurations score 0.246 for total errors, compared with 0.043 for RadMatch. The paired difference is 0.203 [−0.011, 0.406]... Both intervals include zero, leaving the within-study difference between Jev and RadMatch uncertain." Aggregation matters too: "Full's count score reaches 0.320, whereas its soft F1 reaches 0.111. The open NLI judge similarly changes from 0.294 with counts to 0.082 with F1." Error-scope reversal (Table 2, ReXErr): pooling all 8,723 injected errors, NLI's AUROC (0.8969) exceeds Jev's (0.8896); restricting to the 7,085 factual-error-type positives reverses the ordering (Jev 0.9680 vs. NLI 0.9614, diff +0.0066 [0.004, 0.009]); on the 1,638 language-perturbation positives (typos/homophones/repetition, 18.8% of all positives), NLI leads by 0.0674 and both scores fall sharply (Jev 0.5505). "Jev's AUROC for added typos is 0.562, and its recall for repetition is 0.003. Low sensitivity to meaning-preserving edits suits factuality evaluation."

## Kendall correlation headline (Table 1, §5.1)

"Jev–OneQ reaches τ_b = 0.573 on RadEvalX and 0.398 on RadEvalExpert with expert error counts (Table 1). Full reaches 0.582 and 0.397, respectively." Computed as directed Kendall's τ_b (oriented so higher = more agreement; error scores keep their sign, similarity scores are sign-reversed) between each method's report-level score and expert total/significant error counts, with 95% percentile bootstrap CIs over studies (2,000 resamples RadEvalX, 1,000 resamples RadEvalExpert; §4.3). "With the same statements and count aggregation, OneQ improves over open NLI by 0.236 [0.131, 0.345] and 0.075 [0.043, 0.106] on total errors." Open NLI's own Kendall values (Table 1, Panel A): RadEvalX total 0.337 [0.205, 0.457] / significant 0.162 [−0.005, 0.310]; RadEvalExpert total 0.323 [0.260, 0.381] / significant 0.276 [0.207, 0.339]. This is the basis for the abstract's claim of "outperforming an open natural language inference judge under matched decomposition and aggregation" — both Jev and the NLI judge share identical L1 statement extraction and Eq. 2 summation aggregation, isolating the judge model itself as the only difference (§3.4).

## Where Local RadMatch beats Jev

Panel A (complete datasets, Table 1): on RadEvalX, "RadMatch reaches 0.491 versus OneQ's 0.346; the difference is −0.145 [−0.294, −0.004]" for significant errors (RadMatch's total-error score, 0.580, is statistically indistinguishable from OneQ's 0.573: paired diff −0.007 [−0.137, 0.114]). Panel B (shared 200-pair RadEvalExpert subset): "RadMatch leads on both error targets in the shared RadEvalExpert subset. Across these 200 pairs, its total-error correlation is 0.453, compared with 0.322 for OneQ and 0.320 for Full." "OneQ minus RadMatch is −0.131 [−0.226, −0.044] for total errors and −0.226 [−0.320, −0.137] for significant errors. Both intervals exclude zero." RadMatch's significant-error score on this subset is 0.485 [0.385, 0.580] vs. Jev–OneQ's 0.259 [0.152, 0.354] (Table 1, Panel B). So RadMatch's advantage is clear and statistically supported (CI excludes zero) on: (a) significant errors on the complete RadEvalX dataset, (b) total errors on the shared 200-pair RadEvalExpert subset, and (c) significant errors on that same shared subset. It is not clearly ahead on RadEvalX total errors (CI includes zero) nor on within-study candidate ordering on the shared subset (CI includes zero for both targets, §5.5).

## Paper's own stated limitations (§6.1)

"Our evaluation measures agreement with reference text. Reference reports can contain errors or omit relevant findings; establishing correctness against the image and validating clinical use require separate studies. Report-level category scores do not yet reliably distinguish location, severity, and false-finding errors. Probability thresholds benefit from calibration on the intended data, and language-quality assessment requires coverage beyond factual support. The study covers one Jev version, small expert benchmarks, and controlled injected errors. RadEvalX uses one generator and RadCliQ-stratified sampling, with 80 abnormal and 20 normal reports. Broader generator and case distributions would test generality. Sentence-level detection and calibration use Full's support outputs; direct evaluation of OneQ's local probabilities is a further test. Repeating decomposition would extend Jev's fixed-decomposition repeatability study to the full pipeline. Finally, matched end-to-end cost and timing measurements would complement the measured judgment costs and three-finding API demonstration when comparing deployment options."
