# sonthalia2026agent — Agent in a Bottle: Can LLM Agents Turn Their Capabilities Into Cheap, Scalable Artifacts?

arXiv:2610.08775v1 [cs.AI], 06 Oct 2026 (html header). Full text: fulltext/2610.08775.html and .txt (arXiv HTML). Benchmark paper (BOTTLED) on LLMs building reusable task-specific artifacts under fixed budgets; Jev enters as a zero-shot comparator on two of the three tasks (Sec 4.2, App E). Screening note: candidates_v12.csv codes this record as exclude; it is extracted here because it reports measured Jev macro-F1, AUROC and projected cost on stated tasks against stated labels.

## Task and data
Three public tasks (Sec 3.2): MAVE attribute extraction (about 4.77 million product-attribute pairs, F1), Amazon Shopping Queries ESCI query-product relevance with four labels Exact, Substitute, Complement, Irrelevant (about 2.62 million pairs, macro-F1), and RAID AI-generated text detection (about 5.62 million documents, AUROC). Zero-shot LLMs and Jev are scored on the same uniform sample of 1,000 instances per task (Sec 3.5.1, Sec 4.2, App E). Bottled artifacts are scored on the full workload, as means of two runs (Sec 4, Table 1). Jev is not applied to MAVE because it cannot generate free text (Sec 4.2).

## Decision models evaluated
Jev 1.13.0 queried through TypeSafe AI's system_one endpoint, one call per instance of the 1,000-instance sample; ESCI uses the choice question type with four criteria, RAID uses the noul question type with true and false criteria, and the noul probability is read as confidence that the document is generated by a language model (App E, E.1, E.2). No run date is stated; the Jev blog reference carries an access date of October 5, 2026 (References, Almeida 2026), which is not a run date.

## Comparators and tuning parity
Ten LLMs in zero-shot mode (one instance per call, no tools) on the same 1,000 instances: Qwen 3.8 Flash, Qwen 3.8 Max, Sonnet 5, Opus 5, Gemini 3.1 Flash-Lite, Gemini 3.1 Pro, GPT 5.6 Terra, GPT 5.6 Sol, GLM 5.3 Flash, GLM 5.3, all via OpenRouter with release dates and September 2026 prices (Sec 3.5.1, App A, Table A1). The same ten LLMs as bottling agents in the OpenCode harness with 5 million weighted tokens, 10 hours, one A100 40GB GPU, 8 CPU cores, internet through a proxy, and API access only to their own model (Sec 3.3). Two distilled students (Qwen3-0.6B, SmolLM2-360M-Instruct) trained on GLM 5.3 Flash labels within the same 5 million token budget, without tuning (Sec 3.5.2, App B). ESCI zero-shot macro-F1 printed in the text: Opus 5 0.609 (Sec 1), GLM 5.3 0.593, GPT 5.6 Terra 0.573 (Sec 4.1); other zero-shot values appear only in unlabelled figures. Jev receives instructions and criteria reworded from the zero-shot prompt (App C.3, App E.1), a disclosed and bounded asymmetry. Bottled and Jev scores are not on the same items (full workload versus 1,000-instance sample).

## Reference labels
Dataset labels of ESCI, RAID and MAVE (Sec 3.2, Sec 3.4). The paper does not describe how these labels were made; coded not_reported. RAID documents are described as written either by humans or by language models (Sec 3.2).

## n and intervals
1,000 instances per task for zero-shot and Jev (Sec 3.5.1, App E). Zero-shot LLM scores carry 95% bootstrap CIs over 2,000 resamples, shown in Figure 2 only (Sec 4). No interval is printed for Jev's estimates (Sec 4.2, Figure 3). Bottled scores are means over two runs per model and task (Sec 4); student baselines are means over three runs (Sec 4.1).

## Test-data exposure
ESCI (Reddy et al., 2022), RAID (Dugan et al., 2024) and MAVE (Yang et al., 2022) are public pre-2026 datasets (Sec 3.2, Ethics Statement). The contamination audit (proxy blocklist plus a GLM 5.3 Flash judge) covers only the 60 bottling runs and the 21 ablation reruns, with 59 of 60 runs judged clean (Sec 3.3, App D.2); no contamination check is reported for Jev or the zero-shot calls.

## Cost and latency
Jev costs are computed from US$0.042 per million input tokens with output tokens unmetered (App E), and are projected to the full workload from the 1,000-instance sample (Figure 3 caption). ESCI: Jev projected full-workload cost US$104.89 against US$26.28 reported for Opus 5 bottling, about 25% (Sec 4.2); rounded to US$105 in Sec 1, against US$17,273 estimated for Opus 5 zero-shot (Sec 1). RAID: Jev US$223.16 against US$4.69 for Gemini 3.1 Pro bottling, about 2% (Sec 4.2). LLM costs use a weighted token count with cached input at one tenth and output at twice the input weight (Eq. 1, Sec 3.3) and prices from Table A1. No latency is reported for Jev. The bottling cost figures are run costs of the evaluated agents, recorded as comparator values.

## Calibration
No calibration analysis. RAID AUROC uses Jev's noul probability as a score (App E.2); ESCI uses the chosen option only.

## Cascade or escalation
None for Jev. The bottling formulation allows an artifact that routes a hard subset back to the LLM (Sec 3.1, Eq. 4), but agents almost always built self-contained artifacts (Sec 3.1, footnote 2).

## Main Jev results
ESCI macro-F1 0.531; Opus 5 bottled 0.499, about 94% of Jev's score (Sec 4.2). RAID AUROC 0.846; Gemini 3.1 Pro bottled 0.822, over 97% of Jev's estimate (Sec 4.2). In the over-budget ablation Opus 5 reaches RAID AUROC 0.929 (Sec 4.3), and the contaminated GLM 5.3 Flash run reached 0.857 (App D.2); neither is recorded in the ledger.

## Option-name, cardinality, robustness tests
None for Jev. ESCI has four options and RAID two (App E.1, E.2). English only.

## Code and data availability
Code released at https://github.com/aktsonthalia/bottled under the MIT License, with download scripts, harness configuration, prompts, evaluation code and baselines (Reproducibility Statement). Jev prompts are given in full (App E).

## Authors' limitations
No separate limitations section. The paper states that Jev cannot be used for free-text generation such as MAVE, that Jev cost grows linearly with workload size (Sec 4.2), that cost comparisons depend on provider pricing decisions (Sec 4.1), that the blocklist may have missed leakage sources (Sec 3.3), and that full-workload zero-shot evaluation was not run, so zero-shot cost is estimated from the 1,000-instance sample (Sec 3.1).
