# luo2026nudge — Nudge the Judge: Uncovering Program Decision Hijacking in Real-World Jev Applications

- arXiv: 2610.18612v1 [cs.CR], 13 Oct 2026. Full text: fulltext/2610.18612.html and .txt (fetched 2026-10-28).
- Authors: Yang Luo, Tiantian Ji, Zifeng Kang, Yucheng Wang (Beijing University of Posts and Telecommunications; two with Key Laboratory of Trustworthy Distributed Computing and Service, MoE), Yong Liu (Zhongguancun Laboratory). Affiliation type: academic.
- Code and data: JevProbe and JevProbeBench public at https://github.com/xiaoxiaohg8d/JevProbe- (abstract, Section 1).

## Task and data
Security robustness of Jev-backed software, not accuracy. Defines Jev Program Decision Hijacking (JPDH): attacker-controlled context makes schema-valid Jev judgments change a program-consumed decision (decision flip, Eq. 2). JevProbe (4 stages: surface discovery, adversarial context generation, differential execution, impact assessment). 1,711 candidate GitHub repositories, 356 most-starred inspected at fixed revisions, 228 with reachable attack surfaces (Table 1), 2,273 program-grounded test cases (Table 2). Shared subset: 10 applications, 183 test cases for RQ3 to RQ5 (5.1). Metrics: Decision Flip Rate (DFR, flips over valid adversarial executions) and Unsafe Impact Rate.

## Decision models and versions
Target judge: "jev-1.13.0" (5.1). Qwen3-32B generates adversarial variants; Gemma-3-27B-IT assists impact assessment. Cross-model comparison with the Jev backend replaced by seven open LLMs (Qwen2.5-32B and 7B, Gemma3-27B and 4B, Llama3.3-70B, Llama3.1-8B, Llama3.2-3B) and two closed LLMs (GPT-5.6-Sol, Gemini-3.8-Flash) through a compatibility adapter that preserves application decision logic (App. F.1). Reference-list access dates 2026-10-10 to 2026-10-13; the run dates of the Jev calls are not stated.

## Comparators and tuning-budget parity
Attack frameworks AgentDojo, ASB, PIArena, PromptInject adapted under matched attack budgets with payloads limited to 96 characters (5.4). LLM backends receive identical contexts, judgment instructions and criteria and the same adversarial contexts (paired replay), but the adversarial contexts were optimised against Jev ("Jev-targeted attacks", 5.5), so the cross-model comparison favours the flip rate against Jev; the paper says this itself ("under the evaluated Jev-targeted attacks"). No tuning of backends.

## Reference labels
No ground-truth label set. Flips compare benign vs adversarial execution; "confirmed hijacking" uses an "independently established expected decision" (Eq. 3) per application; impact labelled by an LLM-assisted protocol with application-specific rules (Section 4.5, App. B). Ledger label type: none, except the unsafe-impact rate row (llm_teacher: impact labels come from an LLM-assisted protocol).

## n, sampling, intervals
228 applications, 2,273 cases, 1,853 flips. No confidence intervals, bootstrap or repeated runs reported. Popularity stratification in Table 2.

## Test-set exposure
Test cases are newly generated by the authors on open-source application code; not a public benchmark with prior answer keys.

## Cost and latency
Not reported.

## Calibration and cascade
Not applicable; a motivating example shows an attacker lowering a Jev confidence score from 0.70 to 0.16 across the 0.5 application threshold (Figure 2). Numerical judgments count as flips when they cross application-defined thresholds.

## Robustness results
Overall DFR 81.5% (1,853/2,273); 98.6% of flips unsafe; 202 of 228 applications at DFR >= 80%; Jev macro DFR 79.8% vs 50.7 to 66.8% for general LLMs and 29.4% for the strongest adapted baseline attack (Tables 4, 11); defenses reduce DFR only from 78.7% to between 68.9% and 79.8% (Table 5). No option-name, cardinality or language test.

## Limitations (paper's own)
Open-source applications only; model-internal defenses excluded because Jev's architecture and parameters are not public.
